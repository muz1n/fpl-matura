## Reflexion (kurz)

Gut:
- Finale Grössenverhältnisse etabliert: 150x190px optimal für Desktop
- Multi-layer Hover-Effekte (scale + translate + shadow + glow) fühlen sich professionell an
- Flex-based Layout flexibel für verschiedene Formationen

Schwierig:
- Z-Index Management zwischen Linien, Empty State und Spielern
- Balance finden zwischen "gross genug" (Desktop) und "nicht zu gross" (Touch)
- Opacity für Hintergrund-Linien (5% zu schwach, 20% zu stark, 10% richtig)

Gelernt:
- Background-Elemente müssen DEUTLICH im Hintergrund sein (opacity-10, z-index 0)
- Für moderne UIs lieber 20-30% grösser als zu klein
- 48px ist optimal für erkennbare Icons/Logos
- Modernes UI braucht mehrere Feedback-Layer (nicht nur hover:border)
- Nie annehmen dass User Bedienung kennen (Tooltip nötig)

## Entscheidung

Finale Grössenverhältnisse festgelegt:
- Pitch Cards: 150x190px (optimal für Desktop, touch-friendly)
- Bench Cards: 160x200px (etwas grösser da mehr Platz)
- List Cards: Full Width mit 64px Avatar
- Avatare: Minimum 64px, optimal 96px
- Icons/Logos: Minimum 32px, optimal 48px
- Text: Minimum text-sm (14px), optimal text-base-lg (16-18px)
- Touch Targets: Minimum 44x44px (WCAG Standard)

Layout-Struktur:
```
Header (Stats, Formation, Actions)
Spielfeld (volle Breite)
Bank (volle Breite)
Suche (50%) | Kader (50%)
```

## Alternativen (kurz)

- Option 1: Fixed Positioning für Pitch → Zu unflexibel, schlecht responsive
- Option 2: CSS Grid für Spielfeld → Präziser, aber komplexer und weniger flexibel
- Option 3: Kleinere Cards (120x160) → Besser mobile, aber zu klein Desktop
- Option 4: Tabs statt nebeneinander → Spart Platz, schlechtere UX (kein parallel arbeiten)

## Warum so?

Flex-based Layout:
- Flexibel für verschiedene Formationen (3-4-3 bis 5-4-1)
- Automatische Verteilung der Spieler
- Responsive-friendly
- Einfacher zu warten als Grid

Grosse Card-Grössen (150x190px):
- Gut lesbar auf Desktop
- Noch touchable auf Tablets
- Professioneller Look
- Genug Platz für alle Infos ohne Überlappung

Zwei-Spalten-Layout unten:
- Suche und Kader parallel sichtbar
- Effiziente Raumnutzung
- Workflow: Suchen → Hinzufügen → In XI setzen
- Keine Navigation zwischen Tabs nötig

## Fehler & Learnings

**Optimierung 1:** Linien überlappen mit Slots
- Ursache: Z-Index nicht korrekt, opacity zu hoch (20%)
- Lösung: opacity-10, absolute positioning mit z-index 0
- Learning: Background-Elemente müssen DEUTLICH im Hintergrund sein

**Optimierung 2:** Cards zu klein
- Ursache: Konservative Grössen (110-130px), zu wenig Padding
- Lösung: 150px+ Breite, min-h für Text, mehr Padding
- Learning: Für moderne UIs lieber 20-30% grösser als zu klein

**Optimierung 3:** Icons kaum sichtbar
- Ursache: w-6 h-6 (24px) zu klein, opacity zu niedrig
- Lösung: w-8-12 h-8-12 (32-48px), opacity 90%
- Learning: 48px ist optimal für erkennbare Icons/Logos

**Optimierung 4:** Hover-Feedback zu schwach
- Ursache: Nur border-change oder kleine scale (102)
- Lösung: Multi-layer: scale-105 + translateY(-4px) + shadow-2xl + glow
- Learning: Modernes UI braucht mehrere Feedback-Layer für professionellen Look

**Optimierung 5:** Keine Anleitung für User
- Ursache: Drag & Drop nicht offensichtlich, Doppelklick für Captain unklar
- Lösung: Tooltip mit klaren Hinweisen hinzugefügt
- Learning: Nie annehmen dass User die Bedienung kennen

Design-Prinzipien etabliert:
1. Minimum Touch Target: 44x44px (WCAG Standard)
2. Minimum Text Size: 14px (text-sm), optimal 16px+
3. Minimum Icon Size: 32px, optimal 48px
4. Spacing: Minimum gap-4 (16px), optimal gap-6 (24px)
5. Hover States: Multi-layer (scale + translate + shadow + glow)
6. Z-Index Layers: 0 (background) → 10 (overlay) → 20 (interactive) → 30 (modal)
7. Opacity für Backgrounds: Maximum 20%, optimal 10%
8. Border Width: Minimum 2px für Sichtbarkeit

Technische Erkenntnisse:
- Flexbox vs Grid: Flex gewinnt bei dynamischen Formationen, Grid bei fixem Layout
- Z-Index Management: 0-9 (Background), 10-19 (Overlays), 20-29 (Interactive), 30-39 (Floating), 40+ (Modals)
- Performance: Grosse Cards OK bis ~20 Spieler, Shadow/Blur kein Impact
- Hover-Animationen: Hardware-accelerated via transform/opacity
- Accessibility: Touch-Targets > 44px erfüllt, Kontrast > 4.5:1 erfüllt, Keyboard-Navigation/ARIA fehlen noch
