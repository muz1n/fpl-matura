## Entscheidung

**Finale Grössenverhältnisse:**
- Pitch Cards: **150x190px** (optimal für Desktop, noch touch-friendly)
- Bench Cards: **160x200px** (etwas grösser da mehr Platz)
- List Cards: **Full Width** mit 64px Avatar
- Avatare: Minimum **64px**, optimal **96px** auf Cards
- Icons/Logos: Minimum **32px**, optimal **48px**
- Text: Minimum **text-sm (14px)**, optimal **text-base-lg (16-18px)**
- Touch Targets: Minimum **44x44px**, alle Buttons erfüllen dies

**Layout-Struktur:**
```
┌─────────────────────────────────────────┐
│ Header (Stats, Formation, Actions)     │
├─────────────────────────────────────────┤
│ Spielfeld (volle Breite)               │
│ Bank (volle Breite)                     │
├──────────────────┬──────────────────────┤
│ Suche (50%)      │ Kader (50%)         │
└──────────────────┴──────────────────────┘
```

## Alternativen erwogen

1. **Fixed Positioning für Pitch**: Zu unflexibel, schlecht für Responsive
2. **CSS Grid für Spielfeld**: Präziser, aber komplexer und weniger flexibel
3. **Kleinere Cards (120x160)**: Besser für mobile, aber zu klein für Desktop
4. **Tabs statt nebeneinander**: Spart Platz, aber schlechtere UX

## Warum so?

**Flex-based Layout** ist der beste Kompromiss:
- Flexibel für verschiedene Formationen (3-4-3 bis 5-4-1)
- Automatische Verteilung der Spieler
- Responsive-friendly
- Einfacher zu warten als Grid

**Grosse Card-Grössen** (150x190px):
- Gut lesbar auf Desktop
- Noch touchable auf Tablets
- Professioneller Look
- Genug Platz für alle Infos

**Zwei-Spalten-Layout unten**:
- Suche und Kader parallel sichtbar
- Effiziente Raumnutzung
- Workflow: Suchen → Hinzufügen → In XI setzen
- Keine Navigation zwischen Tabs nötig

## Fehler & Learnings

### Problem 1: Linien überlappen mit Slots
- **Ursache**: Z-Index nicht korrekt, opacity zu hoch
- **Lösung**: opacity-10, absolute positioning mit niedrigem z-index
- **Learning**: Background-Elemente müssen DEUTLICH im Hintergrund sein

### Problem 2: Cards zu klein
- **Ursache**: Konservative Grössen (110-130px), zu wenig Padding
- **Lösung**: 150px+ Breite, min-h für Text, mehr Padding
- **Learning**: Für moderne UIs lieber 20-30% grösser als zu klein

### Problem 3: Icons kaum sichtbar
- **Ursache**: w-6 h-6 (24px) zu klein, opacity zu niedrig
- **Lösung**: w-8-12 h-8-12 (32-48px), opacity 90%
- **Learning**: **48px ist optimal** für erkennbare Icons/Logos

### Problem 4: Hover-Feedback zu schwach
- **Ursache**: Nur border-change oder kleine scale
- **Lösung**: Multi-layer: scale + translateY + shadow + glow
- **Learning**: Modernes UI braucht **mehrere Feedback-Layer**

### Problem 5: Keine Anleitung für User
- **Ursache**: Drag & Drop nicht offensichtlich
- **Lösung**: Tooltip mit klaren Hinweisen
- **Learning**: **Nie annehmen** dass User die Bedienung kennen

## Design-Prinzipien etabliert

1. **Minimum Touch Target**: 44x44px (WCAG Standard)
2. **Minimum Text Size**: 14px (text-sm), optimal 16px+
3. **Minimum Icon Size**: 32px, optimal 48px
4. **Spacing**: Minimum gap-4 (16px), optimal gap-6 (24px)
5. **Hover States**: Multi-layer (scale + translate + shadow + glow)
6. **Z-Index Layers**: 0 (background) → 10 (overlay) → 20 (interactive) → 30 (modal)
7. **Opacity für Backgrounds**: Maximum 20%, optimal 10%
8. **Border Width**: Minimum 2px für Sichtbarkeit

## Technische Erkenntnisse

**Flexbox vs Grid für Pitch:**
- Flex gewinnt bei dynamischen Formationen
- Grid besser für fixe Layouts
- Hybrid (Flex rows, inner flex) = beste Lösung

**Z-Index Management:**
```
0-9:   Background (Linien, Patterns)
10-19: Overlays (Empty States, Messages)
20-29: Interactive (Cards, Buttons)
30-39: Floating (Badges, Tooltips)
40+:   Modals
```

**Performance:**
- Grosse Cards OK bis ~20 Spieler
- Shadow/Blur/Gradient: Kein spürbarer Impact
- Hover-Animationen: Hardware-accelerated (transform, opacity)

**Accessibility:**
- Alle Touch-Targets > 44px ✅
- Kontrast-Ratio Text > 4.5:1 ✅
