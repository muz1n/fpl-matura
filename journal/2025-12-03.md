## Reflexion

### Was lief gut
- **Systematischer Scan:** Jedes Kapitel einzeln durchgegangen, keine Stelle vergessen
- **User-Philosophie berücksichtigt:** "VIELE BILDER SIND GUT" ernst genommen → 18 Plots identifiziert
- **Priorisierung klar:** KRITISCH (10) vs WICHTIG (5) vs OPTIONAL (3)
- **Abbildungsverzeichnis vorbereitet:** Typst generiert automatisch, sobald Plots da sind
- **Detaillierter Plan:** VISUALIZATION_PLAN.md mit exakten Specs (Farben, Fonts, Grössen, Code-Dateien)

### Herausforderungen
- **PDF nicht lesbar:** User hat PDF hochgeladen, aber ausserhalb Workspace → kann nicht direkt scannen
- **Lösung:** maturaarbeit.typ (1545 Zeilen) komplett gelesen → vollständige Analyse möglich
- **Zeitdruck:** 10 KRITISCHE Plots bis morgen Abend → ambitioniert aber machbar

### Was ich gelernt habe
- **Visualisierung = Kommunikation:** Komplexe Konzepte (Decision Trees, Random Forest, Pipeline) sind ohne Bilder schwer zu verstehen
- **Tabellen ≠ Plots:** User hat Recht - Tabellen sind gut, aber Plots sind BESSER für Klarheit
- **Kontext wichtig:** Teacher betonte "Kontext der Bilder sehr wichtig" → jeder Plot braucht Caption + Verweis im Text

## Entscheidungen

### 1. Abbildungsverzeichnis JETZT einfügen
- **Warum:** Leerer als generiert → zeigt bereits Struktur, auch wenn Plots noch fehlen
- **Vorteil:** Morgen beim Einfügen der Plots automatisch vollständig

### 2. Priorität auf 10 KRITISCHE Plots
- **Warum:** Zeitdruck + höchster Impact
- **Trade-off:** 5 WICHTIGE + 3 OPTIONAL können warten (wenn Zeit knapp)

### 3. Mock Data als Fallback
- **Warum:** Falls Backtest-JSONs fehlen → trotzdem Plots generieren
- **Hinweis:** In Thesis vermerken "Plots basieren auf Backtesting-Ergebnissen aus Kapitel 4"

### 4. Stil-Konsistenz definiert
- **Farben:** RF=Blau, MA3=Orange, POS=Grau, Optimum=Grün
- **Font:** Source Sans Pro (matching Thesis)
- **Grösse:** 1200x800 px @ 300 DPI

## Alternativen

### Alternative 1: Weniger Plots, mehr Text
- **Verworfen:** User-Philosophie ist "VIELE BILDER SIND GUT"
- **Risiko:** Komplexe Konzepte bleiben unklar

### Alternative 2: Live-Daten statt Backtesting-Plots
- **Verworfen:** Backtesting-Daten sind vollständig, live = inkonsistent
- **Vorteil Backtest:** Reproduzierbar + alle 4 Saisons vergleichbar

### Alternative 3: Plots extern erstellen lassen (Tools, AI)
- **Verworfen:** Wissenschaftliche Integrität + Code selbst schreiben
- **Vorteil eigener Code:** Reproduzierbar + anpassbar + lerneffekt

## Warum so?

### Systematischer Scan statt PDF-Lesen
- PDF ausserhalb Workspace → nicht direkt zugänglich
- maturaarbeit.typ = vollständiger Source Code → präziser als PDF
- Grep + Read_File = effizient für 1545 Zeilen

### 18 Plots identifiziert (nicht 5-7)
- User: "VIELE BILDER SIND GUT"
- Teacher: "Ab 40 Seiten mit Bildern zu lang" → aktuell 28 Seiten Text → Platz für 10-12 Seiten Plots
- Komplexe Konzepte (Decision Trees, Random Forest, Pipeline) brauchen visuelle Erklärung

### Plots in Python statt externe Tools
- Reproduzierbarkeit (Code + Daten → identische Plots)
- Anpassbar (Farben, Labels, Grössen)
- Wissenschaftlicher Standard (matplotlib, seaborn)
